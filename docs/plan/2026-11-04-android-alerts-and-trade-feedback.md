# Android 提醒可靠性与成交反馈开发计划

> 按任务和复选框推进。执行时用 executing-plans 技能，每个任务先复现或写回归测试，再修改代码，最后记录验证结果。

**目标**　修复 Android 批量添加提醒和 WebView 回到前台时的报错，改善后台监控的定时启动、轮询和收盘停止，让策略提醒综合当前行情，并让用户确认的成交自动更新持仓、成本和当日策略。

**架构**　Android 原生壳负责恢复本地 Go 服务与页面导航。Go 核心负责提醒判断、成交记账和策略更新，Vue 提供确认、纠错和历史查询入口。规则、成交、持仓及策略依据都保存在手机的 SQLite 中。

**技术栈**　Go 1.27、GORM、SQLite、gomobile、Kotlin、Android WebView、Vue 3、Vant、Vite。

**需求与架构依据**　规格见下文，现有流程见 [Android 价格提醒 MVP](2026-10-29-android-price-alert-mvp.md)、[ADR-001](../ADR-001-UI浏览器化与AI边车架构决策.md) 和 [ADR-002](../ADR-002-移除桌面网页版模式.md)。

### 规格与拟定默认值

- 范围按附件和现有入口确定为 Android。手机 WebView 继续使用 `127.0.0.1` 随机端口与现有 token 鉴权。用户成交、持仓、成本、备注明细留在设备内。
- 手动价格提醒仍用于盯价。策略提醒单独建模，价格满足只进入观察。盘中确认同时要求新鲜报价、规则配置的量比和买卖盘条件，连续两条不同源时间的行情都满足才推送。跌破方向与盘口方向分别配置，避免把「跌到支撑后买盘回升」当成「卖盘占优」。数量、阈值和时间窗口由规则展示并由用户确认，连续两条是首版可调优的产品参数。
- 区分「价格触及」「条件确认」「条件失效」。规则若要求收盘确认，首版保存为待人工确认并说明行情能力；正式收盘确认接入列在任务 4 的独立交付项。缺字段或盘口不适用时展示原因；用户可明确改成纯盯价。手动止损价仍可设独立的即时风险提醒，文案只报告触价事实。
- 成交以详情页「记录成交」表单为主，通知打开详情时可关联提醒事件。字段包括买卖方向、实际成交股数、价格、成交时间、费用和可选备注，费用无值时由用户明确确认按 0 记。提示词自由输入可以继续用于分析，账本写入统一由成交确认入口完成。
- 首版同时展示「剩余持仓均价」和「本轮资金回收口径的每股净投入」。旧持仓从用户核对的期初快照开始记账。最新策略自动在本地重算，既有远程 AI 分析请求的输入边界由原配置控制，新增账本字段不进入该请求。

### 回归重点

| 情况 | 预期行为 |
| --- | --- |
| 已启用 49 条，选中重复、可新增和超额项 | 逐项显示结果，失败项留在表单中；重复提交或并发请求仍最多启用 50 条（任务 1） |
| 点通知时旧端口已关，随后收到重复或乱序的就绪事件 | 只加载已就绪的当前服务，保留目标股票与关联事件；同地址错误可恢复（任务 2） |
| 闹钟提前触发、错过计划时刻或重复回调；手机熄屏后跨收盘 | 近期开窗前的回调保留单次监控启动，窗口内晚到立即开始检查，过窗跳过并登记下一个窗口。记录实际停服时间（任务 2A） |
| 服务已启动但行情请求阻塞，或休眠后恢复 | 当前轮有明确的截止与结果，恢复后只处理新鲜行情，不并发补跑旧轮次。通知提交结果可追踪（任务 2B） |
| 只触价一次、报价重复、关键字段缺失或来自上一交易时段 | 仍处于观察或等待，不产生确认通知；收盘条件不会由盘中快照完成（任务 3–4） |
| 成交请求重试、两笔并发卖出、补录导致历史仓位为负 | 只应用有效变更，账本和持仓一并提交或回滚（任务 5） |
| 清仓、策略刷新失败，或上一轮评估在新成交后才返回 | 清仓状态可评估，旧策略标记已过期，重试只刷新策略且仅当前持仓版本可以发布（任务 6） |
