# ADR-002：移除桌面网页版模式

| 项 | 内容 |
| --- | --- |
| 状态 | **已接受** |
| 日期 | 2026-10-31 |
| 影响范围 | 桌面启动流程、构建标签、事件桥、文档、移动端构建 |
| 取代 | [ADR-001](ADR-001-UI浏览器化与AI边车架构决策.md) 中「桌面本地 HTTP + 浏览器 UI」部分 |

---

## 1. 背景

ADR-001 曾计划把桌面 UI 从 Wails 窗口迁移到「本地 HTTP 服务 + 默认浏览器」，
并保留 `-tags web` 与 Wails 双模式共存。实际使用中：

- 产品只需要本地桌面应用，网页版模式没有独立用户场景；
- 两套 UI 承载方式增加了启动流程、事件桥、文件对话框和构建验证的维护成本；
- 网页版与桌面版共享前端，但运行时差异需要在 `bridge.js`、`webserver`、
  `backend/events` 和多个组件里持续维护，容易出现只在其中一种模式下出现的问题；
- Android 端已经有自己独立的本地 WebView/HTTP 架构，不需要桌面网页版模式。

因此决定桌面端只保留 Wails 窗口，删除桌面网页版模式。

## 2. 决策

1. 删除桌面网页版专属代码：
   - `app_web.go`
   - `app_tray_web.go`
   - `app_exit_web.go`
   - `app_ui_wails.go`
2. `main.go` 固定使用 `wails.Run`，不再根据构建标签选择 UI 承载方式。
3. 桌面构建不再使用 `-tags web`，文档、AGENTS、构建脚本同步移除该命令。
4. 保留 `webserver` 包给 **Android 端**本地界面使用；它不是桌面网页版。
5. Android 端的事件广播从 `-tags web` 改为 `-tags mobileassets`：
   - `backend/events/emit_mobile.go`（原 `emit_web.go`）
   - `backend/events/emit_wails.go` 使用 `!mobileassets`
   - `mobile/scripts/build-aar.ps1` 使用 `-tags "mobileassets"`
6. `frontend/wailsjs/bridge.js` 继续作为 Wails 绑定/事件桥接层；网页版分支不再有可用后端，
   桌面端始终走 Wails 原生绑定。

## 3. 影响

### 桌面端

- 不再产出 `aipanyi-web` 浏览器模式产物。
- 启动后固定打开 Wails 窗口，不再启动本地 HTTP UI 服务或浏览器。
- `frontend/wailsjs/go/main/App.js` 仍由 `scripts/gen-bindings.js` 改写为桥接调用；
  该流程与桌面网页版无关，保留。
- 文件对话框继续走 Wails 原生能力；`app_file_bridge.go` 中为旧网页版保留的上传入口不再有桌面调用方，
  但不会影响桌面构建。

### Android 端

- 继续使用 `webserver` 提供本地页面和事件广播。
- AAR 构建标签改为 `-tags "mobileassets"`；`mobileassets` 同时负责嵌入移动端静态资源。
- `go build -tags mobileassets ./...` 必须通过。

### 文档与验证

- `AGENTS.md`、`README.md`、`CONTRIBUTING.md` 删除网页版构建和双模式验证说明。
- ADR-001 标记为已废弃，保留历史记录。
- 新的桌面验证命令：

```bash
go build ./...
go vet ./...
go test ./webserver/...
cd frontend && npm run build
wails build -platform windows/amd64 -o aipanyi
```

涉及 Android 端时增加：

```bash
go build -tags mobileassets ./...
go test -tags mobileassets ./webserver/...
```

## 4. 不做什么

- 不删除 `webserver` 包：Android 端仍在使用。
- 不删除 `ai-assistant-web`：它是独立的 AI 助手边车，不是桌面网页版 UI。
- 不删除 `backend/events`：桌面端 Wails 事件和 Android 端广播都依赖它。
- 不删除前端 `bridge.js`：它仍是 Wails 绑定与事件的统一入口。
